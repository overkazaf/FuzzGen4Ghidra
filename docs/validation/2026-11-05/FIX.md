# 修复与回归验证

本次修复覆盖 REPORT.md 中已复现的 8 类问题，并保留原有未提交改动。

- 参数恢复先规范化限定词和指针空格；长度按完整名称/后缀识别，优先匹配 buffer 名称，一对一绑定；`option` 不再误命中。
- 生成局部变量统一使用索引命名，避免 target、buf_len 等合法参数名与内部变量冲突。
- 反序列化先读独立标量，再读取结构体原始存储，最后由各 buffer 分配剩余字节；调用参数仍保持原签名顺序。
- JNI env 模式先移除人工提供的 env/thiz 参数，再重新恢复和配对 fuzz 参数，防止它们抢占 data 的长度参数。
- 回调使用有效的 C 函数指针 typedef；自定义结构体指针导出 opaque 前置声明，同时补齐标准类型头文件。
- JNI 字符串/字节数组区间操作先校验负数、边界与溢出；非法范围不复制，设置可检查和清除的模拟异常状态。该状态并非完整 Java 异常对象。
- 设备脚本改用 Bash 3 兼容的索引数组；以 mock adb 验证依赖推送和去重。

## 行为变化与限制

独立标量现在消耗输入前缀；混合参数函数的已有种子语义发生变化，需重新生成或迁移 corpus。多个 buffer 分配剩余输入，不保证还原业务层面的真实报文布局。

opaque 声明修复编译问题，不等于恢复结构体字段或有效对象。结构体仍采用原有 256 字节占位存储；JNI 仍为简化模拟环境。Android 真机、Ghidra GUI、扩展安装和长时间 fuzzing 尚未验证；本次未自动安装或提交变更。
